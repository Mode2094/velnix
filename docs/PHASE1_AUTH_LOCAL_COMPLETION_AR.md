# المرحلة الأولى — نتيجة البرمجة المحلية ومسار التفعيل الموحد

تاريخ14أكتوبر2026. الفرع audit/production-readiness، baseline d1f8589. لا إعداد Firebase أو عضوية أو Deploy أو Billing نفذ من Codex في هذه الجولة.

دليل المالك الخارجي المقبول: Cloud Shell استطاع الوصول إلى velnix-6c1a2؛ Firestore موجود ولا عضويات أو طلبات ظاهرة، وbootstrapState أعاد404، وفحص Auth أعاد200 مع{}. هذه ليست قراءات Codex أو جلسة Firebase للمرشح. {} صالح لصفر مستخدمين عند إرجاعه من accounts:batchGet، وليس دليلاً على UID أو جاهزية Google provider/App Check/Backend. لم نكرر جرد المشروع من Codex.

الإصلاح المثبت: أداة الجرد كانت قد تفسر payload غير صالح كقائمة فارغة، وكانت تحول خطأ JSON إلى{}. اختبار الانحدار فشل قبل الإصلاح، ثم نجح. القارئ المشترك الآن يرفض JSON المعطوب/arrays/null/errors مع HTTP200، ويتحقق من بنية صفحات Auth/Firestore ومنع تكرار pagination token. يحافظ على HTTP status عند فشل الوصول؛ لا تحويل403/رد غير موثق إلى خلو. ما زال {} الصحيح في استجابة قائمة المستخدمين مدعوماً. بوابة portal تتطلب حالات قراءة صريحة قبل dry-run.

المسار البشري الحالي: رابط Open in Cloud Shell في README يفتح المستودع وفرع التطوير وdocs/CLOUD_SHELL_OWNER_TUTORIAL.md. تحققنا من دعم parameters المستخدمة في [توثيق Google الرسمي](https://docs.cloud.google.com/shell/docs/open-in-cloud-shell). لا ZIP أو رفع ملفات أو سلسلة أوامر؛ إجراء تشغيل واحد من الدليل، ثم البريد المعتمد ومصادقة المشغل/Google التفاعلية عند الحاجة. فتح الرابط وحده لا ينفذ شيفرة ولا يمنح Codex التحكم؛ قد يتطلب المستودع الخاص مصادقة GitHub الرسمية. startup يرفض main وأي تغييرات tracked قبل المصادقة، ويعرض SHA ورابط CI للمراجعة.

المكتمل في المصدر: Google فقط، pending دون دور، مراجعة المدير العام وتعيين الدور والفريق والصلاحيات بمعاملة مدققة، منع التكرار والانتحال والتفويض الذاتي، الرفض والتعطيل وتطبيق تغير الصلاحيات دون انتظار token جديد. [خطة الترحيل](GOOGLE_ONLY_ACCESS_MIGRATION_AR.md) تحفظ الهوية والإدارة القائمة. أداة التوثيق تتحقق من Firebase token حديث ومشروعه ومزوده والبريد والـUID، وتشغل bootstrap_admin.js دون --apply. إعادة فحص الحالة المختصرة داخل هذا الإجراء عند التوثيق تمنع السباق مع تغيير البيانات، ولا تعد إعادة تدقيق شاملة.

المتبقي الحقيقي: تشغيل الإجراء من جلسة المالك المتصلة، وفحص Google provider وتسجيل Web النشط والنطاق وApp Check، ثم إثبات UID من Google Firebase وتشغيل dry-run الفعلي. بعدها فقط يعرض UID والمشروع والدور للموافقة المحددة على إنشاء العضوية. generalManager يمنح جميع صلاحيات Velnix في السياسة القائمة. لا موافقة على النشر أو الفوترة مستنتجة من قبول هذا المسار، ولا تعطيل Email/Password أو Click أو مسح بيانات.

نجاح اختبارات المصدر لا يغلق التفعيل السحابي. النتائج والأعداد في [دليل التحقق](evidence/phase1-auth-local-validation.json). CI لكل من Push وPR للـcommit النهائي مطلوب؛ مانع API السابق باقٍ دون دليل تغير، ولم نكرر الطلب المحجوب. لا نتيجة CI مخترعة أو دليل Google حقيقي مستنتج من المحاكيات.
