# المرحلة الأولى — نطاق Velnix

## داخل النطاق

1. لوحة مؤشرات للطلبات بحسب صلاحيات المستخدم.
2. إدارة طلبات كاملة على مستوى حقول المرحلة الأولى: المستلم، الهواتف، المحافظة والمنطقة والعنوان، وصف الطرد والكمية والمبلغ وطريقة الدفع والملاحظات والشركة وحالة الطلب ورقم التتبع.
3. إنشاء طلب لجميع الأدوار الخمسة، مراجعة وإدارة الطلبات، البحث والتصفية؛ **لا حذف نهائي** للطلبات. الإلغاء والإكمال حالتان محفوظتان مع سجل تغيير.
4. الأدوار الخمسة: مدير عام، مدير بصلاحيات محددة، موظف مستودع (تنسيق وتجهيز الطلب دون نظام مخزون)، مبيعات (يرى مدخلات مدخلي البيانات وفق النطاق المتفق)، مدخل بيانات.
5. إدارة إعدادات شركات التوصيل (إضافة/تعديل/تعطيل/اختبار الربط من الخادم). المرحلة المدفوعة لا تعني ربط شركات غير محدودة؛ الشركة ذات التكامل الفعلي الأولى تُحدد منفردة.
6. إرسال طلب لشركة توصيل واحدة محددة ومُتفق على API الخاص بها، بشرط توفير الوثائق والوصول والخصائص اللازمة.
7. جلب حالات الطلب من واجهة شركة التوصيل و**عكسها داخل النظام تلقائياً** مع رسم خريطة الحالات وسجل المزامنة، باستخدام Webhook أو Polling وفق ما تسمح به واجهة الشركة.
8. الإشعارات التشغيلية والتقارير الأساسية وسجل العمليات بما يتناسب مع المدى المحدد في التنفيذ.
9. Flutter لشاشات التطبيق؛ Firebase Auth + Firestore + Cloud Functions للمنطق والربط الحقيقي لاحقاً.

## خارج المرحلة الأولى

- المتجر الإلكتروني، عرض المنتجات، إنشاء صفحات بيع، كوبونات وعربات التسوق.
- إدارة المخازن والجرد والكميات والأصناف والمشتريات والتحويلات المخزنية. دور «موظف المستودع» **لا** يغير ذلك.
- الربط التشغيلي مع شركات توصيل إضافية دون اتفاق مستقل.
- محاسبة متقدمة، بوابات دفع، تسويق بالعمولة، دردشة فورية، نظام SaaS وفوترة اشتراكات.
- نشر التطبيق على Google Play / Apple App Store، رسوم حسابات المطورين، ومراجعات النشر.

## ملاحظات تعاقدية

هذه الوثيقة مواصفات **تطوير** وليست بديلاً عن العرض المالي؛ راجع العرض المعتمد قبل تحديد الجدول والتكلفة. مرجع الفيديو يُستخدم في طابع الواجهات والتنقل وليس دليلاً على التزام بتنفيذ كل وظيفة فيه. لا نعتبر UI التجريبي إنجازاً للربط الحقيقي.
