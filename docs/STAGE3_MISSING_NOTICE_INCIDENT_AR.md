## 2. الدليل الحاسم

سجلات الوظيفة تحتوي **48 رفضاً** بتاريخ `2026-10-17`، جميعها بالرسالة نفسها:

```
The request was not authenticated. Either allow unauthenticated
invocations or set the proper Authorization header.
The IAM principal lacks {run.routes.invoke} permission.
```

وفي المقابل:

```
ordereventnotice  IAM bindings: []          ← لا أحد يملك run.invoker
createorder       IAM bindings: [{'members': ['allUsers'], 'role': 'roles/run.invoker'}]
```

**الوظائف المستدعَاة من العميل (`europe-west1`) تعمل** لأن Cloud Run يمنح `allUsers` صلاحية `run.invoker`.

## 3. السبب الجذري — مُثبَت

**(Eventarc delivers → Cloud Run `ordereventnotice` → 401)**

مُشغّل Eventarc `ordereventnotice-524138` في `nam5` يرسل الحدث بحساب
`velnix-runtime-internal@`، لكن خدمة Cloud Run Palacioة للدالة
**لا تحتوي أي ربط IAM whatsoever** — لا `run.invoker` ل anybody.
⇒ كل محاولة تسليم تُرفض **قبل تشغيل جسم الدالة**.

### لماذا هذا مستبعد كمُفسِّر

| الفرضية | الدليل المسحوب |
|---|---|
| الحدث لم يُكتب | **مُستبعد** — 6 مستندات أحداث موجودة في Firestore |
| الدالة لم تُنشر | **مُستبعد** — `ACTIVE` منذ `2026-10-15`، والطلب أُنشئ `2026-10-17` |
| منطقة/نوع المشغّل | **سليم** — `nam5` يطابق قاعدة متعددة المناطق؛ عامل التصفية صحيح |
| عضوية المستلمين | **غير قابل للوصول** — الدالة لم تُشغَّل مرة واحدة |
| حساب الخدمة | موجود وظاهر في وصف المشغّل |

### سلسلة الأحداث المؤكَّدة
```
Firestore يكتب events/{id}
  → Eventarc (nam5) يلتقط   ✅
  → ينادي Cloud Run          ❌ 401 run.routes.invoke   (48 محاولة، كلها فاشلة)
  → OrderEventNotice لم يُشغَّل قط
  → 0 إشعار
```
> سجل `created` هو الوحيد الذي نُشئ في البداية؛ وأحداث التحويل الأربعة الأخيرة نُشئت أثناء الاستعادة **بعد** التشخيص، ولم تُنتج إشعاراً أيضاً — وهو **تأكيد إضافي** لنفس العطل.
