# المتطلبات الخارجية الباقية
| المطلوب من المالك | الغرض |
|---|---|
| project ID والمنطقة وإعداد العميل العام لمشروع staging | تهيئة واختبار المسار الحقيقي |
| اعتماد معرفات التطبيقات و OAuth و SHA و App Check | دخول وتوثيق على الأجهزة |
| هوية خدمة ومرجع KMS/IAM عبر أدوات آمنة | تشفير مفاتيح الشركات |
| وثائق شركة واحدة وعقدها وحساب sandbox في مدير الأسرار | تكامل حقيقي موثق |
| إعداد FCM/VAPID واعتماد تجربة الإذن | دفع إشعارات فعلي |
| Android signing و Mac/Xcode وحساب Apple | builds قابلة للتوزيع |
| طراز الطابعة والماسح وأجهزة اختبار | تحقق الإيصالات والباركود |
| اعتماد الهوية والأيقونات والنص القانوني | اكتمال المنتج |
| أهداف الأداء والميزانية و RPO/RTO وسياسة الاحتفاظ | اختبار staging وخطة تشغيل/استعادة |
| موافقة نشر محددة بعد نتائج staging | نقل للإنتاج |

لا ترسل كلمات المرور أو ملفات service-account أو مفاتيح التوقيع في المحادثة. إعداد بيئة التطوير السحابية منفصل عن نشر التطبيق. الـ commits محفوظة على GitHub في audit/production-readiness؛ استعادة صورة الأدوات السحابية في مهمة جديدة تبقى منفصلة عن حفظ Git.

إضافات الاعتماد: فهارس retry/directory على staging، مراقبة notice pushState/Attempts وأعمار pending/processing دون payload شخصي، موافقة على تواتر جدول المزامنة الحالي واختبار ضغط إذا تجاوزت الإشعارات 25 محاولة مستحقة في الدورة، طابعة 58/80 مم بدقة معروفة وماسح لتحديد مدى اعتماد الإيصال الحراري. GitHub API يلزم قراءة CI؛ وصول Git Push وحده لا يمنح إمكانية عرض Actions عبر API.

خطة Staging التفصيلية ومعايير القبول في STAGING_ACCEPTANCE_PLAN.md. تأكد CI الحالي ناجح على 024c1a7 عبر واجهة Actions؛ API نفسه يحتاج تفعيل api.github.com في إعدادات شبكة البيئة. لا تطلب PAT جديداً قبل اختبار المصادقة بعد رفع حجب CONNECT.
