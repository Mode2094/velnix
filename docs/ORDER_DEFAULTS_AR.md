# الإعدادات الافتراضية للطلبات الجديدة (شركة التوصيل + صفحة فيسبوك) — ويب فقط

## 1) الخلاصة
- أُضيف قسم **«الإعدادات الافتراضية للطلبات الجديدة»** في **إعدادات النظام** (لوحة المدير العام):
  قائمتان: **شركة التوصيل الافتراضية** و**صفحة فيسبوك الافتراضية**، مع خيار «بدون …» لكل منهما.
- عند فتح **«طلب جديد»** يُحدَّد الافتراضيان تلقائيًا، وتبقى القائمتان مفتوحتين للاختيار والتغيير،
  و**الاختيار اليدوي له الأولوية** ولا يُستبدل عند تحديث الواجهة.
- الافتراضيان يُطبَّقان على **الطلبات الجديدة فقط**؛ تعديل طلب قديم لا يغيّرهما.
- **اختيار الشركة لا يُرسل الشحنة تلقائيًا**؛ الإرسال خطوة مستقلة لاحقًا.
- التعديل على **Flutter Web فقط** + تعديل متوافق في الدوال؛ لم تُغيَّر واجهة Android ولا أي طلب/عميل/إعداد شحن قائم.

## 2) إعدادات المدير (`saveSettings` / `getSettings`)
- `getSettings` يعيد الآن `defaultCompanyId` و`defaultPageId` (بالإضافة لما كان سابقًا).
- `saveSettings` (صلاحية `manageSettings`):
  - **حقل `defaultPageId` جديد**: يُتحقق أن الصفحة **موجودة ونشطة وغير مؤرشفة**، وإلا يفشل الحفظ برسالة واضحة.
  - **`defaultCompanyId`** (كان موجودًا): يُتحقق أن الشركة **موجودة ومفعّلة وغير مؤرشفة**.
  - **حماية من المسح الخاطئ:** يُلمس كل إعداد افتراضي فقط إذا وصل مفتاحه فعليًا في الطلب
    (`hasOwnProperty`)؛ فحفظ إعداد آخر لا يمسحهما. وتمرير قيمة فارغة يُلغي الافتراضي **عمدًا**.
  - **سجل التدقيق:** يُسجَّل `settings.updated` ويتضمّن القيم الافتراضية التي تغيّرت.
  - التغيير مقيّد بالمخوّلين (`manageSettings`)؛ وبقي البريد/الهاتف/التذييل كما هي.
- الملف: `functions/src/index.js`.

## 3) واجهة الإعدادات (`LiveSettings` + التنقل)
- قسم جديد بعنوان **«الإعدادات الافتراضية للطلبات الجديدة»** فيه القائمتان، مع تنبيه: «تُطبَّق على نموذج
  «طلب جديد» فقط... اختيار الشركة لا يُرسل الشحنة تلقائيًا».
- تُجلب الشركات **المفعّلة غير المؤرشفة**، والصفحات من **النطاق المسموح للمدير** (`listAllowedPages`).
- إن كان الافتراضي المحفوظ لم يعد متاحًا (معطّل/مؤرشف/محذوف/غير مسموح) لا يُعرض محدّدًا، ويظهر تنبيه،
  ويبقى الحقل لاختيار يدوي.
- **الربط في التنقل:** صار **«إعدادات النظام»** عنصرًا في الشريط/القائمة المرئية (كانت الشاشة موجودة لكن غير
  مربوطة). الملفات: `lib/live/live_settings.dart`، `lib/live/live_app.dart`.

## 4) نموذج «طلب جديد» (`LiveOrderForm`)
- عند `widget.initial == null` (طلب جديد) يُقرأ الافتراضيان طازجًا (`settings(fresh: true)`).
- يُحدَّدان **فقط** إذا كانا ما زالا **مفعّلين/مسموحين**، و**فقط إذا كان الحقل فارغًا** — أي أن أي اختيار يدوي
  سبق وصول البيانات لا يُستبدل.
- عند تعذّر الافتراضي يُترك الحقل للاختيار اليدوي مع **رسالة واضحة** (`_defaultNotice`):
  «الشركة الافتراضية المحفوظة لم تعد متاحة…» أو «الصفحة الافتراضية المحفوظة غير متاحة لحسابك…».
- تعديل طلب قائم: لا يُقرأ أي افتراضي، وتبقى قيم الطلب المخزّنة (الصفحة/الشركة) كما هي.
- الحفظ يرسل `pageId` و`companyId` اللذين اختارهما المستخدم، ولا يوجد أي نداء إرسال تلقائي.
- الملف: `lib/live/live_orders.dart`.

## 5) الملفات المتغيرة
- `functions/src/index.js` — `getSettings`/`saveSettings`: `defaultPageId` + تحقق + حماية المفاتيح + التدقيق.
- `lib/live/live_settings.dart` — قسم الإعدادات الافتراضية + الحالة/التنبيهات + حفظ الحقلين.
- `lib/live/live_app.dart` — ربط «إعدادات النظام» في التنقل (مفتاح تبويب + الصلاحية).
- `lib/live/live_orders.dart` — تطبيق الافتراضيين على الطلب الجديد فقط + أولوية الاختيار اليدوي + التنبيه.
- `test/default_order_defaults_test.dart` — جديد (8 اختبارات).
- `functions/test/emulator/workflow.test.js` — اختبار جديد لحفظ/تحقق الافتراضيين.
- تنسيق `dart format` لملفات الطباعة/الباركود السابقة (ليبقى CI نظيفًا).
- لم تُلمس أي قيمة طلب أو حساب عميل أو إعداد شحن، ولم يُبنَ APK/AAB.

## 6) الاختبارات
### أ) واجهة Flutter — `test/default_order_defaults_test.dart` (8/8)
1. المدير يحفظ شركة وصفحة افتراضيتين (يلتقط `saveSettings` القيمتين).
2. «طلب جديد» يعرضهما **محدَّدتين مسبقًا**.
3. تغيير يدوي للشركة والصفحة ثم الحفظ ⇒ يذهب اختيار المستخدم (لا الافتراضي).
4. إعادة فتح طلب جديد ⇒ يعود الافتراضي.
5. تعديل طلب قديم ⇒ تبقى قيم الطلب المخزّنة (`updateOrder` بالقيم القديمة).
6. موظف لا يملك صلاحية الصفحة الافتراضية ⇒ لا تُحدَّد + رسالة «غير متاحة لحسابك».
7. شركة معطّلة/صفحة مؤرشفة ⇒ لا تُحدَّدان + «بدون شركة الآن» + تنبيه.
8. اختيار الشركة لا يستدعي `sendOrderToDelivery` إطلاقًا.

### ب) الخادم — `workflow.test.js` (اختبار جديد)
- حفظ الافتراضيين ثم قراءتهما؛ حفظ إعداد آخر **لا يمسحهما**؛ تمرير مفتاح فارغ يمسحه عمدًا.
- رفض شركة معطّلة/غير موجودة وصفحة معطّلة/غير موجودة.
- الموظف العادي لا يستطيع تغييرهما (`permission-denied`).

### ج) النتائج الإجمالية
- `dart format --set-exit-if-changed lib test`: **نظيف**.
- `flutter analyze`: **نظيف**.
- `flutter test`: **539 يمرّ** (+8 لهذه المهمة)، ونفس **25 فشلاً بيئيًا سابقًا** (golden على macOS +
  mobile_scanner) — لا فشل جديد.
- `functions`: `npm test` = **243 يمرّ**، `npm run test:emulator` = **308 يمرّ** (يشمل الجديد).

## 7) التحقق على الموقع منشور فعليًا
1. المُدير يفتح **إعدادات النظام** ⇒ قسم الافتراضيات ظاهر.
2. اختيار **Click Delivery** و**Market تاج** ثم **حفظ** ⇒ رسالة «تم حفظ إعدادات المؤسسة».
3. التأكد من التخزين في Firestore:
   `defaultCompanyId = click_delivery_1603` (Click Delivery, enabled) و
   `defaultPageId = M16gs8E93iXqa3TWYOL6` (تاج Market, active).
4. فتح **«طلب جديد»** ⇒ **الصفحة الإلكترونية: تاج Market** و**شركة التوصيل: Click Delivery** محدَّدتان تلقائيًا.
5. تغيير يدوي للصفحة إلى **المملكة** ⇒ القيمة تتغيّر، والشركة تبقى Click Delivery.
6. **إعادة تحميل كامل** للصفحة ثم فتح «طلب جديد» ⇒ الافتراضيان يظهران مجددًا (استمرارية).
7. التأكد أن عدد الطلبات بقي **45** ولم يُنشأ/يُرسل أي طلب تلقائيًا.
