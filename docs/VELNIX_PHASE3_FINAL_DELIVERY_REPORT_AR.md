## 2. ما تم تنفيذه

### 2.1 بوليصة الشحن (`lib/printing/order_printing.dart`)

- قالبان: **بوليصة احترافية** للورق العادي، و**بوليصة حرارية مختصرة** لبكرات 58/80مم.
- الرأس: شعار Velnix + اسم الصفحة الإلكترونية + شعار الصفحة (عند وجوده) + نوع الطلب + رقم الطلب.
- رمز QR = نفس قيمة الباركود `VNX-<docId>` — **لا يحتوي اسم العميل أو هاتفه أو عنوانه أو أي سر أو رابط**.
- الباركود Code128 بعرض كامل فوق رمز QR في المنتصف، مع هوامش هادئة، لضمان المسح على كل المقاسات.
- المصدر الموحّد للبيانات: `decorateOrdersForPrint()` في `lib/live/live_app.dart` يجلب الإعدادات وشعار **صفحة الطلب نفسها** عبر `pageId` — لا يوجد خلط بين صفحات المتجر، والطلب بدون صفحة/شعار يُطبع باسم الصفحة فقط.
- `BulkPrintScreen` يدعم الآن اختيار نوع البوليصة (احترافي/حراري) بجانب حجم الورق.

### 2.2 تحقق المسح الضوئي

أُعيد توليد كل ملفات PDF عبر `test/live_readiness_test.dart` ثم فُكّت بـ `scripts/verify_barcodes.py` (Code128 + QR) على 203/300/600 DPI:

| الورق | 203 DPI | 300 DPI | 600 DPI |
|---|---|---|---|
| A3 / A4 / A5 / A6 | PASS | PASS | PASS |
| Letter / Legal | PASS | PASS | PASS |
| custom 50×80 | PASS | PASS | PASS |
| thermal58 / thermal80 | PASS | PASS | PASS |
| thermal 58/80 بمعرّف قياسي | PASS | PASS | PASS |
| طلب مخفي المبلغ | PASS | PASS | PASS |

**النتيجة: 36/36 PASS** (`build/qa/verify-barcodes.log`). الطلبات الطويلة تتوزع على عدة صفحات، والرموز تُطبع كاملة في صفحة مستقلة بدل قصّها.

### 2.3 سجل الحركة والواجهة

- `eventDetailLabel` / `eventDetailValue` في `lib/live/live_app.dart`: ترجمة مفاتيح التفاصيل (الحالة الجديدة، شركة التوصيل، رقم التتبع، المصدر، النتيجة…) وتحويل القيم إلى عربية مقروءة، مع إخفاء القيم الفارغة.
- بطاقة اللوحة الرئيسية: **«جميع طلبات المتجر»** بدل «الطلبات غير المسندة لشركة» — تعرض نطاق طلبات المتجر (داخلية/غير مسندة لشركة توصيل) بكل الحالات، وتبقى بطاقة «كل الطلبات» هي المجموع الشامل. لا تتغير أرقام الخادم أو نطاقات الصلاحيات.
- تحديث الـ goldens الخاصة باللوحة (15 صورة) و`live_dashboard_390.png` على Linux، مع بقاء بقية الصور دون تغيير.

### 2.4 كلمات المرور

- **الموظف:** `ChangePasswordScreen` في `lib/live/live_account.dart` — إعادة مصادقة بكلمة المرور الحالية ثم `updatePassword`، تحقق 8 أحرف، منع التطابق مع الحالية، رسائل أخطاء عربية، وشاشة توضيحية لحسابات Google فقط. لا تُسجَّل كلمة المرور ولا تُحفظ.
- **المدير العام / المدير المفوض:** `resetEmployeePassword` يعمل الآن لمن يملك `manageEmployees` مع حواجز رتب:
  - لا إعادة تعيين للذات (يُوجَّه لشاشة التغيير الذاتي).
  - غير المدير العام لا يمسّ `generalManager` أو `manager` أو من في رتبته.
  - `warehouse` يتطلب صلاحية `updateOrderStatus` أو أن يكون المنفّذ من المستودع.
  - رفض حسابات Google فقط (`failed-precondition`) والموظف غير الموجود (`not-found`).
  - إبطال رموز التحديث `revokeRefreshTokens` بعد التغيير.
  - سجل تدقيق `member.password_reset` يحتوي `targetRole` فقط — **بدون كلمة المرور**.

## 5. المراجعة الأمنية المختصرة

- رمز QR والباركود يحملان `VNX-<id>` فقط؛ لا بيانات عميل ولا توكن ولا رابط.
- شعار الصفحة يُختار بـ `pageId` الخاص بالطلب؛ لا شعار صفحة أخرى.
- المبلغ لا يُطبع إذا حجبه الخادم (يُطبع من الحمولة الواردة فقط).
- إعادة تعيين كلمة المرور: صلاحية + حواجز رتب + تدقيق بلا سر + إبطال جلسات.
- التغيير الذاتي يعيد المصادقة قبل التحديث، ولا يخزّن كلمة المرور.
- لا تغيير على قواعد Firestore أو App Check أو KMS.
