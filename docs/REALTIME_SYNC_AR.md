# المزامنة اللحظية بين الأجهزة + نقل الطلب بين البطاقات — 0.7.0+14

## المشكلة قبل التغيير

Firestore deny-by-default: لا يستطيع العميل قراءة `orders/companies/notices`
مباشرة، وكانت القراءات عبارة عن callables مخزّنة مؤقتًا (TTL 10–15 ثانية).
لذلك أي تغيير من جهاز لا يظهر على جهاز آخر إلا بعد إعادة تحميل يدوية.

## الحل

### الخادم (functions/src/sync.js)

- مستند واحد صغير `sync/global` يحمل عدّادات فقط.
- ثلاثة مُشغّلات (`onDocumentWritten`, europe-west1, retry:true) تزيد العدّاد
  المقابل عند أي كتابة:
  - `syncOrdersRev` على `orders/{orderId}`
  - `syncCompaniesRev` على `companies/{companyId}`
  - `syncNoticesRev` على `notices/{noticeId}`
- المُشغّل يتجاهل محتوى المستند عمدًا (لا قراءة، لا تسريب)، والزيادة
  idempotent-safe: أي تكرار لا يفسد حالة، فقط يجعل العميل يعيد القراءة.

### القواعد (firestore.rules)

```
match /sync/{docId} {
  allow get: if signedIn();
  allow list, create, update, delete: if false;
}
```

قراءة للمسجّلين فقط، عدّادات بلا بيانات عمل، والكتابة من الخادم فقط.

### العميل (lib/live/sync_service.dart)

- مستمع Firestore **واحد** لكل جلسة (لا polling، لا مستمع لكل صفحة).
- أول لقطة من الخادم = خط أساس (لا تُحدث تحديثًا)؛ اللقطة من الكاش = «لا يوجد
  اتصال» ولا تُحدّث.
- يزيد فقط المجال الذي تغيّر.
- يتوقف عند الخلفية ويعود عند الاستئناف.

### الواجهة

- مؤشّر في الشريط العلوي: **محدّث / جارٍ التحديث / لا يوجد اتصال — ستتم
  المزامنة عند عودته**.
- لوحات المعلومات، شبكة البطاقات، الإشعارات، وقائمة الطلبات تعيد القراءة في
  مكانها (بدون إعادة تحميل كاملة).
- قائمة الطلبات تُسقط الصفوف التي لم تعد تطابق الفلتر المفتوح (الحالة/التوصيل/
  الإرسال/الشركة/الحذف من الشركة) عبر مطابقة `matchingFilters` في الخادم، بحيث
  يكون الطلب في **بطاقة واحدة فقط** ولا يتكرر.
