|---|---|---|

| تعديل متزامن أو بعد إرسال الشحنة | revision ومعاملات، تجميد الطلب ومراجعة الإرسال الملتبس | اختبارات معاملات وتعارض |
| فقدان إشعار بعد حفظ الطلب | trigger دائم لأحداث الطلب ومعرف إشعار حتمي | تكرار الحدث لا يعيد read state |
| أعداد ناقصة بسبب حد القراءة | تجميع الخادم مع نطاق المستخدم والفلاتر | اختبار 10005 طلبات |

أُضيفت شاشة إعدادات حقيقية وحفظ بيانات المؤسسة، مسار إشعارات FCM اختياري، ملفات Android/iOS/Web وCI. التفاصيل في TEST_RESULTS وREMAINING_EXTERNAL_REQUIREMENTS. وثائق التقييم القديمة سجل تاريخي؛ هذه المجموعة تصف التغييرات الحالية.

## تصنيف المخاطر
| الدرجة | البنود | الوضع |
|---|---|---|
| Critical | تصعيد صلاحيات/تسرب نطاق فريق قديم، فقدان آخر مدير | إصلاح ومعاملات واختبارات محلية |
| High | تكرار إرسال/تعديل شحنة مجمدة، مراجعات متعارضة، أعداد ناقصة | إصلاح؛ بوابة carrier/staging باقية |
| Medium | فقد إشعار، أخطاء عرض ضيق وPDF طويل، فلاتر غير متسقة | إصلاح واختبارات محددة |
| Low | تنسيق الكود، إصدارات وأوامر README قديمة | تحديث |

هذه درجات أثر هندسي للمشكلات التي راجعها العمل، وليست نتائج اختبار اختراق معتمد. بوابات OAuth/App Check/KMS والفهارس والتوقيع والاستعادة والطباعة تمنع الاعتماد رغم نجاح الفحوص المحلية.

## تحسينات المراجعة النهائية
- Critical: حل الحلقة المغلقة للطلب الداخلي بانتقال مخول ومصدر إكمال، مع بقاء شحنات الشركات مجمدة.
- High: استبدال push completed عند الخطأ بسياسة retry/lease/fencing وأجهزة مؤكدة؛ الحفاظ على read state وتنظيف tokens.
- High: كشف عيب قراءة 58 مم/203 DPI بمعرف نموذجي؛ فصل النص وQuiet Zone ومحاذاة أعمدة، وفحص الدقات الثلاث مع توثيق fallback.
- Medium: إزالة حد 100 الصامت لقوائم الموظفين والشركات ومنشئي الطلبات، بصفحات وفرز وبحث، وإزالة cache عند فشل التحديث.
- Medium: تثبيت تشخيص آخر اتصال ومزامنة برسائل آمنة ومنع تكرار أفعال الإدارة، وتأكيد الإكمال الداخلي.
- Medium: CI يفحص builds Demo وLive ويقرأ barcode من artifacts ويفحص توقيعات أسرار وتبعيات الإنتاج.

لم تنشر الفهارس/Functions أو تُنشأ خدمة مدفوعة جديدة. يبقى KMS وFCM/OAuth/App Check/carrier والأجهزة والأداء الحقيقي خارجياً.
