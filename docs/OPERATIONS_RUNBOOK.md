# تشغيل ومتابعة Velnix

البيئة المحلية: source scripts/cloud-env.sh ثم scripts/validate.sh. لا تستخدم الإنتاج للفحوص. النتائج والقيود في TEST_RESULTS. سجل التقدم في Git والوثائق؛ الفرع audit/production-readiness، لا push أو deploy تلقائي.

للموظف: دخول بحساب مفعّل، إنشاء طلب، مراجعة البيانات، متابعة الحالة، اختيار المرشحات، طباعة من التفاصيل. المدير ينشئ/يعدل الموظفين ويراجع الدور والصلاحيات والفريق ثم الحفظ؛ إيقاف الموظف يسحب الوصول بعد تحديث الملف وتحقق الخادم. Google وحده لا ينشئ موظفاً مخولاً.

المشغل يراجع إعدادات المؤسسة والهاتف وذيل المستند، والشركة وعقد adapter وخرائط الحالة. Click محجوب حتى اكتمال العقد والتفويض؛ لا اختبار اتصال أو تفعيل أو استخدام generic_v1 بديلاً عنه. إرسال ملتبس لا يعاد تلقائياً: افحص سجل المزود والتتبع أولاً ثم إجراء المراجعة المخول. الأرشفة تحفظ التاريخ ولا توقف استقبال حالة الشحنة القديمة.

المشروع الحالي واحد velnix-6c1a2؛ اسم staging لا يعزل البيانات. لا تنسخ بياناته ولا تنشئ fixtures أو حسابات عليه في التحضير5A. بعد موافقة محددة، استعمل حسابات وطلبات اصطناعية معتمدة فقط، ولا تشغّل اختبارات reset/wipe/import أو حمل10000 طلب على المشروع المشترك. افحص حالة النشر والفهارس الموجودة أولاً؛ أي نشر أو تعديل لاحق يحتاج تفويضاً مستقلاً ومراجعة المتطلبات المالية. خطة الرحلة الفعلية وحدودها في [تحضير5A](STAGE5A_OPERATIONAL_READINESS_AR.md).

النسخ والاستعادة: يحدد المالك RPO/RTO والمنطقة وسياسة الاحتفاظ. خطة Firestore managed export/backup وbucket وIAM تبقى غير منفذة وقد تتطلب خدمات مدفوعة وموافقة منفصلة. لا يوجد مشروع staging منفصل معتمد؛ اختبار الاستعادة إلى هدف سحابي معزول يبقى اعتماداً مفتوحاً يحتاج قراراً صريحاً، ولا ينشأ مشروع جديد تلقائياً. لا تستورد فوق المشروع الحالي. احتفظ بقواعد وفهارس وإصدارات Functions ومرجع KMS دون استخراج مفتاح؛ حسابات Auth وإعداد OAuth وKMS ليست مشمولة تلقائياً في Firestore export ويجب تخطيط استعادتها منفصلة.

Rollback: احتفظ بالنسخة السابقة والـlockfiles والقواعد والفهارس المتوافقة ومخطط البيانات، أوقف عمليات إرسال جديدة إذا ظهرت حالات ملتبسة، ولا تعد إرسال شحنات كجزء من rollback. هذه خطة مقترحة غير منفذة على مشروع خارجي، وتحتاج تجربة استعادة فعلية قبل الاعتماد.

الدفع: راقب pending/processing/sent/failed وpushAttempts وlease، ولا تعيد إشعاراً sent عشوائياً. فشل جزئي عند نفاد المحاولات يوسم failed حتى لو وصل لبعض الأجهزة؛ قائمة الأجهزة المؤكدة تحفظ لتفادي resend العادي. الاستعادة محدودة4، تعتمد جدول15دقيقة الحالي، ولا تمس read state. legacy sending/global failure قابلة للاستعادة؛ نتائج partial الرقمية القديمة بلا سجل جهاز لا تضمن تحديد من استلم، وتحتاج مراجعة staging وخطة migration قبل إعادة إرسال تاريخي. تكرار نادر ممكن إذا مات العامل بين FCM والحفظ؛ noticeId ثابت، ولا يوجد ادعاء exactly-once.
