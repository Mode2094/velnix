## 4. آلية احتساب المبالغ والتوصيل (D7 — أهم نتائج هذه الجولة)

**دليلان قاطعان من البوابة نفسها:**

**(أ) دوال الحساب في صفحة النموذج حرفياً:**
```js
// عند تعديل «قيمة الشحنة» (Order Amt):
Total Amt = parseFloat(Order Amt) + parseFloat(Shipping Amt)
// عند تعديل «الإجمالي» (Total Amt):
Order Amt = parseFloat(Total Amt) - parseFloat(Shipping Amt)
// عند تغيير «شحن على»:
على المستلم (1): Order Amt مُفعَّل، Total Amt معطَّل (يُحسب تلقائياً)
على الراسل  (2): Order Amt معطَّل، Total Amt يُفعَّل ويُحسب منه Order Amt
```
⇒ **الإجمالي = قيمة الشحنة + قيمة الشحن** في البوابة (والعكس بالطرح). معادلة مؤكدة بالكود.

**(ب) تسمية API `Ord_Amt` تطابق حرفياً التسمية الإنجليزية لحقل «قيمة الشحنة» = "Order Amt"** — وليس حقل «الإجمالي» (Total Amt) ولا «قيمة الشحن» (Shipping Amt).

**الاستنتاج المرجَّح بقوة (يتطلب تأكيداً واحداً من المزع):**
- `Ord_Amt` المطلوب إرساله = **قيمة الشحنة (بضاعة)**؛
- Click يضيف **قيمة الشحن** من قائمة أسعاره الخاصة (`PriceList=70` لهذا الحساب)، فلا يُرسل العميل الشحن ولا الإجمالي؛
- المستلم يدفع الإجمالي = `Ord_Amt` + الشحن، والمستحق للتاجر = قيمة الشحنة.

هذا التفسير يتوافق مع: السطر الإنجليزي («order amount + shipping amount» = الإجمالي المكوَّن)، ومع عمودَي القائمة «الإجمالي / قيمة الشحن / المستحق للراسل»، والغلبة الاسمية `Order Amt ↔ Ord_Amt`.

**السطر العربي في الوثيقة («سيتم خصم قيمة التوصيل منها») يظل مخالفاً حرفياً** لهذا التفسير، ولا نعتمد حسمه نهائياً إلا برد المزع: سؤال واحد محدد جاهز في §9.

> ⛔ لذلك: **لا يزال الحجب المالي قائماً.** لم يُغيَّر أي منطق مبالغ في Velnix.

## 5. الحالات المتاحة (D9 — تقدم كبير، دون أكواد API)

**من أزرار فلترة «شحناتى» (13 زراً) ومن مخطط لوحة التحكم، 12 حالة عرض مؤكدة من المنصة:**

| # | العربية (زر الفلترة) | الإنجليزية | المعرّف الداخلي للمنصة (زر LinkButton) |
|---|---|---|---|
| 1 | قيد انتظار الموافقة | (لم تُلتقط التسمية الإنجليزية) | `LnkWating` |
| 2 | في مخزن الشحن | In shipping store | `LnkConfirmed` |
| 3 | في الشحن | In shipping | `LnkInShipping` |
| 4 | تم التسليم | Delivered | `LnkDelivered` |
| 5 | تسليم جزئي | Part delivered | `LnkPartDeliverd` |
| 6 | مؤجل | Postponed | `LnkPostponed` |
| 7 | ملغي | Canceled | `LnkCanceled` |
| 8 | مرتجع | Returned | `LnkReturned` |
| 9 | مرتجع جزئي | Part returned | `LnkPartReturned` |
| 10 | في مخزن المرتجعات | In returned store | `LnkInStore` |
| 11 | في الشحن للراسل | In shipping to sender | `LnkInShippingReturned` |
| 12 | تم استلام المرتجع | Delivered to sender | `LnkClientReturned` |

**مقارنة بالسبع التي زوّد بها العميل:** السبع (قيد انتظار الموافقة، مخزن الشحن، في الشحن، تم التسليم، تسليم جزئي، مؤجل، ملغي) مطابقة وتغطي **مسار الذهاب**؛ والمنصة تضيف **مسار المرتجعات الخمس** (مرتجع، مرتجع جزئي، في مخزن المرتجعات، في الشحن للراسل، تم استلام المرتجع). مخطط لوحة التحكم يستخدم صيغاً قريبة: «في مخزن المرتجع» و«تم التسليم للراسل».

**حالة السداد:** فلتر التقرير الرسمي يعرض قيمتين بقيم رقمية: `غير مسدد = 1` و`تم السداد = 2` (وهذان **لحالة السداد الداخلية للتاجر**، لا لحالة الشحنة).

**عمود «محاولات الشحن»** يظهر في تقرير المتابعة ⇒ المنصة تتبع عدد محاولات التسليم.

**تحذير مقصود:** المعرّفات أعلاه (`LnkWating`…) وقيم الفلاتر **رموز واجهة المنصة**، وليست **أكواد API موثقة**. لم يُشتق منها أي تحويل برمجي، وما زال `getorder` بلا استجابة ناجحة موثقة لربط الأكواد.

## 6. معلومات API من داخل الحساب

| الفحص | النتيجة |
|---|---|
| قسم/صفحة توثيق API داخل الشاشات المتاحة للعميل | **لا يوجد** — لا صفحة API أو Help في قائمة العميل |

## 9. ما الذي ما زال يتطلب إجابة من Click (بعد أدلة البوابة)

الأسئلة الآن **أدق** وأقصر — كل واحد منها لا يمكن إثباته من البوابة وحدها:

1. **`Ord_Amt` (الحسم المالي الوحيد المتبقي):** نموذج البوابة يفصل «قيمة الشحنة Order Amt» عن «الإجمالي Total Amt = Order Amt + Shipping Amt». هل `Ord_Amt` في API يقابل «قيمة الشحنة» (ويضيف Click الشحن من قائمة أسعاره)، أم «الإجمالي»؟ **أرفقوا شحنة واحدة API وتقرير قائمة أسعارها.**
2. **كود حالة واحد على الأقل** كما تعيده استجابة `getorder` الناجحة (JSON منزوع) — لربط الأكواد بالحالات الاثنتي عشرة المثبتة من البوابة (§5).
3. **`Client_Serial`:** ما نتيجة إرسال `setorder` مرتين بنفس `Client_Serial` ببيانات متطابقة ومختلفة؟ (البوابة تعرضه «Reference no» اختيارياً؛ API لم يعلن).
4. **method الـ`setorder`** ومتطلبات `Content-Type` — ما زال غير مصرح به كتابياً.
5. **صيغة منطقية `Is_Ord_Exchange`/`Open_Shippment`** على السلك (الصيغة الحرفية "True or False" أم booleans JSON) — النموذج checkboxes، والـAPI غير مصرح.
6. **اعتماد API صالح لحساب 1603** — البوابة تدخل بنجاح لكن `/Client/` رفض الاعتماد سابقاً؛ ما الاعتماد الصحيح للـAPI إن كان منفصلاً؟
7. هل يوجد **sandbox** للإرسال التجريبي الآمن؟
8. هل يتقبل `Reciver_Address` نصياً حراً رغم أن البوابة تلزم **مدينة+منطقة من قوائم منفصلة** (17 محافظة)؟ وما سلوك العنوان غير المطابق للمناطق؟
