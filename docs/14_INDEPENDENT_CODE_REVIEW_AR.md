# Velnix — تقرير مراجعة مستقلة للكود قبل Open Code

**الإصدار:** مراجعة v0.4 (نسخة واجهات وبيانات تجريبية). **الفيديو:** `1000307681.mp4`، مدته الفعلية 78.72 ثانية، والجدول المرجعي في `10_VIDEO_SECOND_BY_SECOND_AR.md`.

## خلاصة القرار

**صالح كمدخل لعملية تدقيق وتشغيل بواسطة Open Code، وغير صالح للإطلاق أو الادعاء أن التصميم مجاز بصرياً.**
لم يتوفر Flutter SDK أثناء هذه المراجعة. نجح فحص توازن الأقواس والاستيرادات المحلية على 19 ملف Dart، لكن **لم يُشغَّل** `flutter analyze`، `flutter test`، `flutter run`، ولا اختبار فعلي لأحجام الهاتف واللابتوب؛ ولا يوجد إثبات بأن كل شاشة بلا overflow أو crash. الاختبارات الموجودة هي ملفات اختبار **بانتظار التنفيذ**.

## عيوب/التزامات مفتوحة قبل اعتماد تجربة التصميم

1. **حرج للإطلاق:** Firebase Auth/Firestore/Rules/Functions والتقسيم المؤسسي غير مطبقة؛ تغيير الأدوار داخل الواجهة لا يفرض أماناً حقيقياً. العروض التجريبية قابلة للتعديل من العميل وغير موثوقة كمصدر بيانات.
2. **حرج للتشغيل:** شركات التوصيل غير متصلة، لا يوجد Webhook/Polling/توقيع/Retry/Dedup/سجل أخطاء، وحقل API key مجرد واجهة لا يخزن أسراراً. التكامل الحقيقي يتطلب شركة واحدة محددة ووثائقها.
3. **حرج لتقييم التصميم:** لا صورة شاشة مولدة من Flutter أو فحص widget فعلي. احرص على اختبار 320/360/390/430/768/1024/1440/1920، الاتجاه RTL، الهاتف أفقيّاً، وتكبير الخط حتى 200%، وأزرار الهواتف ذات المساحة الصغيرة.
4. **عالٍ لتجربة الاستخدام:** الأحجام النصية الثابتة الكثيرة 10–12 نقطة والخط العربي غير المثبت كمورد، وغياب موافقة بصرية مصوّرة لجميع الشاشات. تطبيق هوية Typography والهوامش المتناسقة وموضوع الواجهات مهم قبل الربط الخلفي.
5. **عالٍ للإطلاق:** `DemoStore` محلي بلا حفظ/تحميل، ولا توجد حالات حقيقية للأخطاء/التحميل/عدم الاتصال أو معالجة تضارب التعديلات.
6. **متوسط:** الفلاتر والقوائم كلها بالذاكرة، ولا يوجد تقطيع صفحات (pagination) أو تحسين تحميل آلاف الطلبات.
7. **متوسط:** استخدام `double` للمبالغ في نموذج العرض فقط؛ في النظام النهائي استخدم وحدات مالية صحيحة لتجنب أخطاء الكسور.
8. **تعاقدي:** المنصات المطلوب تسليمها يجب تحديدها، ورفع Google Play/Apple App Store وحسابات المطورين ورسومها ليست ضمن السعر السابق.
