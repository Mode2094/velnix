# تكامل التوصيل
adapter generic_v1 في providers.js عقد مرجعي للصحة وإنشاء الشحنة وجلب الحالة. اختبارات provider تستخدم خادم HTTP حقيقياً على loopback مع transport محقون؛ مسار الإنتاج يحتفظ HTTPS allowlist ولا يحتوي تجاوزاً لاختبارات الإنتاج.

يلزم من المزود: documentation version، sandbox URL، توثيق المصادقة، الحقول والمبالغ ووحدتها، idempotency key، حالات وتتبع وإلغاء، rate limits، webhook HMAC/retry ومعرف الحدث. يجب تنفيذ دورة حقيقية ناجحة/فاشلة/timeout وإعادة webhook في sandbox قبل تفعيل الشركة.

الشركة تؤرشف ولا تحذف؛ الاستعادة تبقيها معطلة حتى تحقق الصحة. المفاتيح تحفظ مشفرة KMS. الطلب قيد الإرسال أو المرسل مجمد، والفشل غير المؤكد يحتاج قرار مراجعة قبل إعادة إرسال. webhook المبكر أثناء الإرسال يرجع 503 ليعيد المزود المحاولة، ولا يحرق event ID؛ التكرار والحالات المتأخرة لا ترجع الحالة للخلف. polling محدود 100 شركة/دورة ومعالجة أخطاء لكل شركة. لم يثبت الاتصال بأي شركة حقيقية.

الطلب الداخلي أصبح قابلاً للإكمال دون شركة؛ completionSource يفرق الموظف عن تأكيد carrier. الشركة المعينة أو أي أثر إرسال/تتبع يمنع الإكمال اليدوي. آخر health check ونتيجة فشله الآمنة محفوظان، وآخر sync/attempt يظهران في تفاصيل الطلب. HTTP 429/timeout يعالجان كفشل اتصال؛ إعادة الشحن غير المؤكد تحتاج مراجعة، وpolling يعود في دورة لاحقة. سياسة Retry-After وعقد idempotency لشركة فعلية لا تُختلق دون وثائقها.
