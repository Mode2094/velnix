# معالجة فشل CI وبوابة إغلاق المرحلة الرابعة

## حالة الإغلاق

تحديث المرحلة5A،14أكتوبر2026: أكد المالك خارج Codex نجاح تشغيلَي Push وPR على `e35c973b7251d30b4c0b7e52eb7036db934b7f6f`، بما يشمل Firebase وFlutter وAndroid. بذلك اجتازت بوابة CI لإغلاق المرحلة الرابعة وفق دليل المالك، ويمكن متابعة التحضير5A. لم تقدم أرقام التشغيل الجديدة، ولم نتحقق منها عبر API؛ [فحوص الـcommit](https://github.com/Mode2094/velnix/commit/e35c973b7251d30b4c0b7e52eb7036db934b7f6f/checks). هذا لا يغلق اختبارات الخدمات والأجهزة في المرحلة الخامسة.

لم نقرأ السجل الأصلي الكامل لفشل PR على8fa8d99 بسبب مانع الوصول الموضح أدناه؛ السبب المثبت محلياً متوافق مع العَرَض الذي أبلغ عنه المالك. تبقى مطابقة ذلك السجل التاريخي غير منفذة، دون إلغاء تأكيد المالك لنجاح الإصلاح النهائي.

Baseline هو 8fa8d99 على audit/production-readiness. بحسب مراجعة المالك: Push38603105895 ناجح، PR38603110856 فاشل في firebase → npm run test:emulator، والاختبار team queries spanning more than 30 creators paginate without loss or duplication انتهى internal بعد نحو175ثانية. هذه نتائج من المالك وليست قراءة API ناجحة في البيئة.

## إعادة الإنتاج والسبب المثبت

أنشئت نسخة Git نظيفة بلا SDK files المحلية أو اعتمادات مشروع حقيقي، وثبتت dependencies عبر npm ci وlockfile وNode22.23.3 وJava21. المحاكيات demo-velnix على loopback فقط. شُغّل workflow.test.js كاملاً مع بيانات10005 طلبات السابقة للاختبار، دون انتقاء الحالة وإسقاط بيانات الحمل.

التشغيل الأصلي بذاكرة JVM الافتراضية8GiB نجح:25/25، نحو85.25ثانية، والاختبار المتأثر41.84ثانية، وذروة أكبر عملية ابن5920040KiB. لا يمثل النجاح ثباتاً على بيئة أصغر.

تحت حد JVM1536MiB ومعالجين منطقيين، بلغ GC نحو1534MiB، وحدثت أخطاء Java heap space في FirestoreEmulatorQueryExecutor.materializeIndexTable وFirestoreEmulatorQuerySemantics.runAggregationQuery، أثناء الاختبار المتأثر. استمر GC دون تقدم؛ أوقف التشغيل التشخيصي بعد توثيق OOM، ولا يصنف كتجربة ناجحة أو فشل assertion مكتمل مطابق لسجل CI. هذا يثبت انهيار المحاكي محلياً ولا يزعم قراءة الاستثناء الداخلي الأصلي من GitHub.

السبب في المصدر: dashboardStats يشغل تسع حالات × مجموعتي شحن/داخلي × مجموعتي creators دفعة واحدة عبر Promise.all متداخل؛36 RPC لتجميعات مستقلة. المحاكي يكوّن جداول فهرسة في الذاكرة فوق10005 سجل. companyStats يستخدم التدفق غير المحدود نفسه. حدود IN30 صحيحة، ولا يوجد دليل محلي على فقد/تكرار cursor أو خطأ توقع الاختبار.

## الإصلاح المحدود

- functions/src/aggregations.js: طابور داخلي يقرأ جميع queries بحد4 RPC متزامنة عبر كل المجموعات، ويعيد counts/amountMinor إلى مجموعتها الأصلية. الفشل يرفض النتيجة كاملة؛ لا counters جزئية ناجحة.
- functions/src/index.js: استعمال الطابور في dashboardStats وcompanyStats بدلاً من Promise.all المتداخل. predicates ونطاق الأدوار وshowAmount والأكواد والحقول ونتائج التجميع نفسها.
- functions/test/aggregations.test.js: أربعة اختبارات انحدار لحد التزامن عبر54 query، اكتمال القراءة مرة واحدة، ترتيب المجموعات مع اكتمال مختلف، الفشل الكامل، والصفر/المبالغ المحجوبة.
- CI: حفظ functions/firestore-debug.log عند الفشل كـartifact لمدة7أيام. البيانات في هذه المجموعة اصطناعية وعلى المحاكي؛ لم يضف upload لملفات Auth أو SDK/credentials. if:failure لا يلغي فشل test ولا يستخدم continue-on-error.

لم يتغير workflow.test.js أو توقعاته أو seed10005/35، ولم ترفع مهلة test أو callable أو CI. حد الذاكرة1536 والمعالجين استُعملا للتشخيص والتحقق فقط، ولم ترفع الذاكرة في CI أو تُحذف بيانات الحمل للتغلب على العيب. عدد الاستعلامات نفسه؛ تغير ترتيب تنفيذها فقط. قياسات الكلفة/latency على Firestore المنشور مؤجلة إلى المرحلة الخامسة.

## مانع GitHub وما يلزم لإزالته

Git read/push يعملان عبر الربط الموثق. صفحات المستودع وPR وحتى التشغيل القديم تعيد404؛ محاولة استعمال الربط الموجود للقراءة لم تغير ذلك. API يرفض CONNECT403 من بوابة الشبكة قبل HTTP GitHub، فلا يمكن الحكم منه على صلاحية Actions أو token. المسودة الحالية للبيئة تصف شبكة unrestricted؛ هذا ليس إثباتاً لتطبيقها على runtime، ولم نستبدلها بقائمة نطاقات أو نضف secret مكرراً.

لاستعادة القراءة الآلية، يلزم مالك بيئة Codex معالجة رفض HTTPS إلى api.github.com مع المنصة. هذا ليس Deploy لـFirebase. بعد فتح الاتصال يعاد فحص الربط الموجود، ثم تعالج401/403 من GitHub نفسه إن ظهرت مع صلاحية Actions:read للمستودع. لا ترسل PAT أو token في المحادثة. تحقق المالك الخارجي من نجاح تشغيلَي الإصلاح قُبل كما ورد أعلاه؛ السجل التاريخي الكامل وأرقام التشغيل الجديدة غير متاحة هنا.

## المؤجل إلى المرحلة الخامسة

بعد إغلاق بوابة CI فقط: Firebase الحقيقي/Auth والعضويات وApp Check والفهارس وIAM/KMS الفعلية، ومفتاح Web App Check العام والنطاقات ونشاط التسجيل الحالي، وFCM على الأجهزة، وتوقيع Android وMac/Xcode/iOS وAPNs، والأداء والنسخ/الاستعادة المعزولة ومراجعة المالك. المشروع الواحد المعتمد لا يوفر عزلاً تلقائياً للبيانات. Click يظل محجوباً حتى العقد والاستجابات والأكواد والمعاني المالية الرسمية ثم تفويض sandbox؛ لا generic_v1 بديلاً. الطابعة والأجهزة والربط الحقيقي غير مكتملة.

لا Merge أو Deploy أو موارد مدفوعة أو تعديل مشروع Firebase الحقيقي أو طابعة/Click فعلياً في هذه المعالجة. تاريخ العمل:14أكتوبر2026.
