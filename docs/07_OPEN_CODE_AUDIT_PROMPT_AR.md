# بروموت رقم 0 — تقرير شامل بدون أي تعديل

انسخ النص التالي في Open Code **بعد فك ضغط مشروع Velnix وفتحه كمساحة عمل**:

---

أنت مهندس Flutter خبير ومراجع معمارية. المشروع المفتوح اسمه Velnix – Smart Order Management، الإصدار UI Redesign 0.2.0، وهو قاعدة واجهات عربية RTL لتطبيق إدارة الطلبات.

## مطلوب في هذه المرحلة: تقرير تدقيق فقط

1. اقرأ `README.md` وجميع ملفات `docs/` وافحص `pubspec.yaml`, `lib/`, `test/`.
2. تأكد أن Flutter SDK متوفر وتعرف الإصدار والـplatforms الممكنة. إن كانت ملفات Android/iOS/Web غير موجودة، ضع خطة توليدها ولا تنشئها الآن.
3. اذكر أي أخطاء compile أو import أو analyzer أو Flutter API compatibility بدقة مع مسار الملف ورقم السطر. إن أمكن نفذ أوامر فحص **غير معدِّلة فقط**، مثل `flutter --version`, `flutter analyze`, `flutter test`. تجنب أوامر الكتابة والتوليد قبل الموافقة.
4. افحص اتساق 9 حالات داخل بطاقتي الرئيسية (طلبات التوصيل + جميع الطلبات (التوصيل مجموعة فرعية من جميع الطلبات))، وكل شركة على حدة، وأن مجموع البطاقات يساوي عدد الطلبات الصحيح، والضغط على الحالة يفتح الفلتر المناسب.
5. راجع جميع شاشات mobile-first وRTL: overflow، أحجام الخط، Scroll، bottom navigation، AppBar، الضوابط وأخطاء التنقل.
6. افحص صلاحيات الأدوار الخمسة (مدير عام/مدير/مستودع/مبيعات/مدخل بيانات) وتأكد أن كل دور يرى بياناته وقوائمه الصحيحة وأن الجميع يضيف طلباً، دون صلاحيات غير مصرح بها.
7. تحقق من عدم إمكانية الحذف النهائي للطلبات، ومن أن أرشفة شركات التوصيل لا تحذف طلبات مرتبطة بها.
8. لا تدّع وجود Firebase أو مزامنة API حقيقية؛ هذه المرحلة واجهات وتجربة محلية. احصر كل ما يلزم لاحقاً لجعل النظام إنتاجياً دون إضافة متجر إلكتروني أو مخزون.
9. أعطني تقريراً مرتّباً: **Critical / High / Medium / Low**، الملفات والأسطر، نتائج الأوامر الفعلية، المشاكل المرئية والتصميمية، ثم خطة إصلاح قصيرة مرتبة حسب الأولوية.

**ممنوع تماماً في هذه المرحلة**: إنشاء ملفات، تعديل ملفات، حذف ملفات، تشغيل `flutter create`، إضافة packages، تغيير التصميم، ربط Firebase، أو بدء تطوير جديد. إذا احتجت أمراً يكتب ملفات، اسألني أولاً.
