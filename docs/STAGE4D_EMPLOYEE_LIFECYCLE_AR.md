# Stage 4D — دورة حياة الموظف عبر الواجهة

> **الحالة: PARTIAL** — المُحدِّدات حُسمت من المصدر بالأدلة؛ الأتمتة الكاملة لم تكتمل هذه الجلسة.

## 1. هل حُسم مُحدِّد الحفظ؟ ✅ **نعم — من المصدر**

| السؤال | الإجابة من المصدر |
|---|---|
| نوع العنصر | `FilledButton.icon` |
| الأيقونة | `Icons.save_outlined` |
| التسمية | **`حفظ الموظف`** |
| الشرط | `onPressed: busy ? null : save` |
| الموضع | `lib/live/live_admin.dart:1140` |
| الاستدعاء | `saveMember` |
| مدخل النموذج | `إعدادات الموظف` (tooltip) في السطر `851` |

### ⚠️ **لا يوجد عيب وصولية**
العنصر **نعم له تسمية عربية كاملة**. الفشل السابق كان **مُحدِّداً خاطئاً في أداتي** (خمّنت «حفظ» بدل «حفظ الموظف») — **ليس عيباً في التطبيق**.

> لن أدّعي عيباً لم يحدث.  
## 2. 🔑 اكتشاف مصمَّم — لا «إضافة موظف» مباشرة

| الفحص | النتيجة |
|---|---|
| `saveMember` بمعرّف غير موجود | **`not-found` — لا ينشئ حساباً من العدم** |
| `saveMember` بدون `id` | **لا مسار إنشاء** |
| زر «إضافة موظف» في الواجهة | **غير موجود** |
| آلية التفعيل الفعلية | `joinSession` ← طلب انضمام ← **موافقة المدير العام** |

**الاستنتاج:** «إنشاء موظف» **ليس إجراءً مباشراً بالتصميم** — التفعيل يتم عبر طلبات الانضمام. لذلك يبقى الإجراء الإلزامي الصحيح هو **دورة الطلب/الموافقة**، لا نموذج إنشاء مباشر.
