# المرحلة الثانية — واجهة Live مع Firebase Emulators

## النطاق والدليل

العمل على `audit/production-readiness` انطلاقًا من `30dcce1`. الاختبار في Chromium
بواجهة `VelnixLiveApp` الفعلية وAuth/Firestore/Functions محلية على المشروع الاصطناعي
`demo-velnix-preview`. لا استخدام لـDemoStore، ولا استبدال لاستجابات Backend
بنتائج Mock ناجحة. حساب المدير الحقيقي وFirebase الحقيقي لم يُستخدما أو يُعدّلا.

## مصفوفة الأدوار

| الدور الاصطناعي | ما اختُبر عبر الواجهة وBackend المحلي |
| --- | --- |
| مدير عام | الدخول، لوحة التحكم، إنشاء وتعديل الطلب، الحالات، سجل العمليات والإدارة |
| مدير بمنح صريحة | الدخول والإنشاء ورؤية الطلبات والمبالغ والإدارة وفق المنح |
| مستودع | الدخول والإنشاء ورؤية الطلبات وتغيير الحالة، وحجب مبالغ الآخرين والإدارة |
| مبيعات | الإنشاء ورؤية طلباته وفريقه، حجب مبالغ الفريق وطلبات خارج الفريق والإدارة |
| مدخل بيانات | الإنشاء ورؤية وتعديل طلباته، حجب طلبات الآخرين وتغيير الحالة والإدارة |

هذه نتائج لتهيئة صلاحيات محددة وموثقة في `seed.cjs`؛ ليست افتراضًا بأن كل مدير
يملك كل المنح. حساب معلّق وحساب معطّل اصطناعيان اختُبرا أيضًا دون دخول مساحة العمل.

## الوظائف والحماية

- إنشاء طلب من الواجهة لكل دور، والتحقق من المستندات والمبالغ الصحيحة بوحدات
  الألف والكمية، وعدم وجود شركة أو رقم تتبع أو شحنة حقيقية.
- البحث المسموح وحجب نتائج خارج النطاق، عرض التفاصيل، التعديل وسجل الحركة.
- دورة داخلية: جديد ← قيد المراجعة ← قيد التجهيز ← جاهز ← مكتمل؛ قفل التعديل
  في النهاية. إلغاء طلب مستقل يحافظ على مستنده وسجله. حالات Click الخارجية
  والمبالغ الجزئية ليست مثبتة بهذا الاختبار.
- تكرار الحفظ بنفس المفتاح لا ينشئ طلبين؛ اختلاف المحتوى بالمفتاح نفسه يُرفض.
  تعديلان متزامنان يقبلان مراجعة واحدة ويرفضان القديمة. نموذج واجهة قديم
  لا يكتب فوق التعديل الأحدث.
- رفض قراءة/حذف الطلبات وتعديل العضوية مباشرة عبر Firestore لجميع الأدوار؛
  رفض انتحال الهوية والتفويض الذاتي والإدارة غير المصرح بها وغياب App Check.
- تعطيل عضو أثناء جلسة مفتوحة يغلق مساحة العمل، والطلبات التالية تُرفض؛ رفض
  طلب انضمام ينعكس على واجهة صاحبه. Backend يعطّل Auth كذلك، لذلك قد تظهر
  رسالة ضرورة حساب Google فعال بدل شاشة العضوية المعطلة؛ كلاهما يمنع الوصول.
- إشعار داخل التطبيق أنشأه trigger الحقيقي للمحاكي، وعرضه ووسمه مقروءًا عبر
  الواجهة مع readback، ومنع قراءة إشعار مستخدم آخر. تفعيل إشعارات الجهاز
  يعرض غياب التهيئة بوضوح. توصيل FCM الفعلي غير مختبر.

## الإصلاح المثبت

قطع طلب `dashboardStats` أظهر للمستخدم `internal [0]`. أصبح خطأ SDK الداخلي
رسالة عربية توضح إعادة المحاولة ومراجعة المسؤول عند الاستمرار. رسائل الصلاحيات
وتعارض المراجعة بقيت محفوظة. الاختبار يقطع الشبكة فعلًا ثم يعيدها وينتظر لوحة
التحكم من Backend؛ لا يعرض نجاحًا مصطنعًا.

لم تتغير قواعد Firestore أو فهارسها أو منطق أعمال Functions أو إعدادات المشروع
الحقيقي. وسائل Auth/App Check الاصطناعية في مدخل منفصل يرفض النطاقات غير المحلية.
CI يفحص بناء Live العادي للتأكد من خلوه من علامات المحاكيات.

## الملفات وأسبابها

- `lib/live/gateway.dart` و`test/live_presentation_test.dart`: رسالة الخطأ واختبارا انحدار.
- `scripts/emulator-preview/`: تشغيل آمن قابل للتكرار، هويات اصطناعية، اختبار
  Chromium والتحقق من البيانات المحفوظة وفصل بناء Live؛ إرشادات التشغيل في README.
- `functions/test/emulator_preview_isolation.test.js`: رفض وجهات سحابية أو نطاق
  غير محلي، وفشل فحص البناء إذا احتوى علامات الاختبار.
- `.github/workflows/ci.yml`: وظيفة Chromium مع المحاكيات وأدلتها، وفحص عزل Live.
- هذا التقرير و`docs/evidence/stage2-emulator-ui.json`: نتائج الاختبار وحدوده.

## حدود القبول

نجاح المحاكيات لا يثبت Google OAuth الحقيقي، App Check الحقيقي، IAM أو الفهارس
المنشورة أو FCM والأجهزة والطباعة وiOS. لا اتصال بـClick ولا مزامنة خارجية ولا
Merge أو Deploy أو APIs أو فوترة. لا انتقال إلى المرحلة الثالثة قبل مراجعة المالك.

توقيت السيناريوهات قياس محلي لرحلات متسلسلة في Chromium، وليس اختبار حمل أو وعدًا
بأداء الإنتاج. الأخطاء والتزامن والطلبات المكررة ضمن الحالات المثبتة أعلاه فقط.

## نتائج Chromium والبناء المحلي

- Chromium: **21 ناجحًا، صفر فشل، صفر page errors**؛ readback ناجح لخمسة طلبات وسجلاتها.
- مجموع زمن السيناريوهات المحلي: **102.06 ثانية** (يتضمن الدخول وتحميل الواجهة، وليس زمن استجابة API منفردًا).
- بناء Web لوضع Live نجح؛ فحص خلو الحزمة من علامات المحاكيات نجح. تحذير خط Cupertino غير مانع للبناء؛ لا خلل أيقونات مثبت في الرحلات المصورة.
- التشغيل البسيط من المستودع: `bash scripts/emulator-preview/start.sh` ثم فتح `http://127.0.0.1:8767` في نفس بيئة المتصفح المحلية.

**119**، Emulator **68**، اختبارات إعدادات Python **12**، وفحوص PDF/الباركود

فحوص PDF هنا برمجية فقط؛ لم تُستخدم طابعة.

**قرار القبول المحلي:** السيناريوهات المطلوبة المثبتة ناجحة بعد إصلاح رسالة الخطأ،
ولا فشل متبقٍ في الجولة النهائية. إثبات الخدمات والأجهزة الخارجية مؤجل صراحة،
ولا تُعتبر هذه نتيجة جاهزية إنتاج أو تصريحًا للمرحلة الثالثة. نتائج Push وPR
مرتبطة بالـcommit النهائي في GitHub، وليست مستنتجة من نجاح الاختبارات المحلية.
