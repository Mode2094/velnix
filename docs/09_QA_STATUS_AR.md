# حالة التحقق من إصدار التصميم 0.2.0

## تمّ التأكد منه في بيئة الإنشاء

- جميع الملفات المتوقعة موجودة، وملف pubspec.yaml صالح للقراءة بصيغة YAML.
- فحص تركيب الأقواس والأقواس المربعة والمعقوفة آلياً على ملفات Dart باستخدام lexical tokenization لم يظهر عدم اتزان.
- تمت مراجعة العلاقات البرمجية بين role-scoped demo store والشاشات وعملية التصفية.
- تم إعداد اختبارات مكتوبة لكل من: ظهور الأدوار الخمسة، إنشاء الطلب لكل دور، اختلاف نطاق المشاهدة، صلاحيات التعديل والشركات، تجميع الحالات، عدم حذف الطلبات، وأرشفة الشركة.

## ما لم نستطع التحقق منه هنا

- **لم يتم تشغيل Flutter SDK ولا `flutter analyze` أو `flutter test` أو بناء Android/iOS/Web** لعدم توفر Flutter SDK في البيئة.
- لم تُلتقط لقطات شاشة من تشغيل Flutter على جهاز حقيقي/محاكي، ولم يُختبر RTL وoverflow بصرياً بعد.
- لا يمكن اختبار API حقيقي قبل تحديد الشركة ووثائق التكامل ولا Firebase قبل التهيئة.

## تعليمات لازمة عند فتح المشروع في Open Code

1. أجرِ `flutter --version`, ثم أنشئ منصات التشغيل المطلوبة بعد الموافقة، ثم `flutter pub get`.
2. شغّل `flutter analyze` و`flutter test` وأصلح أي أخطاء فعلية دون إضافة ميزات جديدة.
3. اختبر كل شاشة على عرض 360px و390px و768px و1440px ودقّق من RTL والنصوص العربية والتنقل.
4. اختبر الأدوار الخمسة فعلياً مع تغيير الموظف، والضغط على بطاقة حالة داخل القسم والشركة، ومقارنة عدد النتائج بالأرقام.

**هذه مراجعة مبدئية للشفرة، وليست شهادة نجاح تشغيل أو جاهزية إنتاجية.**
