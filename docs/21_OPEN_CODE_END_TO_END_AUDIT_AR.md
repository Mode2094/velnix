# بروموت Open Code — Velnix v0.6 (ابدأ بالتشخيص فقط)

أنت مهندس Flutter + Firebase QA Lead. افتح مجلد هذا المشروع كاملاً ولا تستخدم الملفات التجريبية (`VELNIX_MODE=demo`) مرجعاً للحكم على وظائف الإنتاج؛ النطاق الفعلي هو `VELNIX_MODE=live`.

## المرحلة 0: إظهار الحقائق، بلا نشر أو تغييرات إنتاج

1. اقرأ README وdocs/19 وdocs/20 والفيديو المرجعي ووثيقة نطاق المرحلة الأولى.
2. افحص بيئة المشروع ثم نفّذ `flutter create .` فقط في نسخة عمل/فرع جديد إن كانت ملفات المنصات ناقصة، ثم `flutter pub get`, `flutter analyze`, `flutter test`. لا تصحح شيئاً صامتاً؛ أحضر الملفات/الأسطر/الأسباب.
3. نفّذ `npm --prefix functions install` ثم `npm --prefix functions run syntax` و`npm --prefix functions test`. شغّل Firebase Emulator Suite وقواعد Firestore دون استخدام مشروع Production.
4. اختبر تنقل الشاشات على 320،375،390،600،768،1024،1440،1920 في RTL مع keyboard وmouse وtext scale حتى 200%. التقط صورة لكل شاشة وكل مقاس، ونظّمها بحسب الدور. لا تدّعِ فحصاً بصرياً بلا صور.
5. جرّب إنشاء طلب من كل دور؛ صحح أخطاء البدء، تحقق من بطاقة حالة الطلب، ابحث عن الطلب بالاسم/الهاتف/الرقم، غيّر حالته، اربط شركة، أرسله على Sandbox، ثم تحقّق من عكس الحالة من Webhook/Polling.
6. اختبر أزرار: إضافة/تعديل/إلغاء/حفظ/رجوع/بحث/مسح/فلتر/تحميل المزيد/تحديث/إشعارات/تفاصيل/إسناد/إرسال/تأكيد استثناء الإرسال/إضافة شركة/أرشفتها/استعادتها/اختبار الاتصال/تعديل الموظف/تعطيله/الخروج/نسيت كلمة المرور.
7. جرّب الصلاحيات الخمس بالعميل وباستدعاءات Cloud Functions مباشرة؛ امنع تسرب المبالغ وطلبات الفرق، وامنع أي رفع صلاحية غير مصرح. راجع `functions/src/order_view.js` وملف `firestore.rules`.
8. تحقق من فهارس البحث: `customerKey` و`phoneDigits` للطلبات الجديدة والقديمة. راجع backfill في `functions/scripts/backfill_search_keys.js`؛ **لا تنفذ `--apply` إلا بعد نسخ احتياطي وإذن**.
9. لا تضف متجر إلكتروني ولا مخزون ولا نشر متاجر ولا بوابة دفع غير متفق عليها. لا تضف دعم شركة توصيل غير محددة على أنه جاهز.
10. Google Sign-In حالياً غير منفذ. اكتب تقريراً بخطوات التكامل الآمن على المنصات المطلوبة، مع ربط حساب الموظف المحدد بـ UID، ولا تفعّل تسجيل Google بصورة عامة دون موافقة أو إعداد فعلي.

## مخرجات المرحلة 0

أعد تقريراً مصنفاً إلى P0/P1/P2، لكل مشكلة: اسم الملف والسطر، طريقة إعادة الإنتاج، الأثر على العميل، اقتراح إصلاح محدد، والصورة أو سجل الاختبار. حدّد لكل شاشة «ناجحة / فيها خلل / غير مختبرة» ولكل دور مصفوفة إجراءات. اقترح خطة عمل مرقمة مع تقدير المخاطر. **لا تقل أن المنتج نهائي ما دام هناك خطأ أو تكامل غير مختبر. لا تنشر Firebase، ولا تستخدم مفاتيح حقيقية، ولا تشغل فاتورة مدفوعة دون موافقة المستخدم.**
