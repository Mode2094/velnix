## 2. barcode — محتوى مُتحقَّق منه

| الفحص | النتيجة | لماذا يهم |
|---|---|---|
| مبني على `documentId` | ✅ `VNX-RLWEouzNty2huVT8DUHN` | الباركود = هوية الطلب |
| **ثابت عند إعادة الطباعة** | ✅ نداءان ⇒ نفس القيمة | لا يتغيّر مع الوقت |
| **لا يتأثّر بالوقت** | ✅ `printedAt` لا يغيّره | إعادة الطباعة لا تُنتج طلباً جديداً |
| **يتجاهل باركوداً بعيداً مُزيفاً** | ✅ `VNX-some-other-order` مرفوض | لا يسمح قيمة تخدم طلباً آخر |
| يرفض معرّفات غير آمنة | ✅ فراغ · مسافة · `/` · 141 محرفاً | Code128 لا يقبل ذلك |
| يقبل معرّفات Firestore الحقيقية | ✅ | توافق عملي |

## 4. PDF — تحقّق من الناتج الحقيقي

| الفحص | النتيجة |
|---|---|
| بايتات صالحة `%PDF-` | ✅ |
| حجم واقعي (>1KB) | ✅ |
| **مرجع الطلب في البيانات الوصفية** | ✅ `RLWEouzNty2huVT8DUHN` |
| ينتج لـA4 ولـA5 | ✅ |
| **لا مبلغ إن أخفاه الخادم** | ✅ يبنى بنجاح بلا تلفيق |
| طلب بقيمة صفر | ✅ |
| **لا مبلغ على طلب مخفي الإذن** | ✅ `if (amount is num)` — الفقرة المالية لا تُرسَم إطلاقاً |
| طابع زمني ناقص | ✅ لا ينهار |

## 5. ⚠️ نتيجة مهمة — رفض الإيصال الضيّق **سلوك صحيح**

ورق `80mm` (الthermal الشائع) **أرفضه التطبيق برسالة صريحة**:
> «الورق ضيق لباركود قابل للقراءة؛ اختر ورقاً أعرض لهذا الطلب»

هذا **ليس عيباً** — التصميم يرفض إخراجاً غير قابل للمسح بدل تصغيره صامتاً.

> **ملاحظة منتجية:** أي طلب على ورق 80mm **لن يطبع**. إن كان ذلك مستخدماً فعلياً فيجب اختيار A5/ thermally 100mm+.
