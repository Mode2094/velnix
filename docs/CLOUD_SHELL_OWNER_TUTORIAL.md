# Velnix — إجراء المرحلة الأولى الموحد

هذا الدليل يعمل من فرع audit/production-readiness، دون ZIP أو رفع ملفات. فتحه لا يمنح Codex وصولاً إلى Cloud Shell، ولا يشغّل المصدر تلقائياً؛ تشغيل الإجراء يحتاج تفاعلاً منك في Cloud Shell. إذا كان المستودع خاصاً فقد يطلب Cloud Shell تسجيل GitHub الرسمي؛ لا تلصق token في المحادثة.

## تشغيل موحد

شغّل الخطوة الوحيدة التالية من المستودع المفتوح، عبر زر نقل المقطع إلى الطرفية، ثم Enter:

```bash
bash scripts/owner-setup/start.sh
```

أدخل بريد المرشح الذي اعتمدته. يعاد استخدام جلسة gcloud البشرية النشطة دون ADC login إضافي؛ يجب أن تكون مخولة مسبقاً لقراءة المشروع. لا تدخل كلمات مرور في الطرفية أو المحادثة، ولا تعطِ أي ملف Service Account خاص. تفويض المشغل مختلف عن جلسة Firebase للمرشح.

## توثيق Google

عند جاهزية الطرفية افتح Web Preview على8080 في تبويب مستقل. إذا احتاج مزود Google أو نطاق المعاينة إعداداً، يحدد الإجراء موضعه الدقيق في Console، ويتوقف قبل تسجيل الدخول. لا يغير هذه الإعدادات تلقائياً، ولا يعطل Email/Password أو App Check.

بعد اجتياز الإعدادات، اضغط «المتابعة باستخدام Google» واختر حساب المرشح. سيُتحقق من رمز Firebase وUID الحقيقي، ثم يُشغّل bootstrap الجاف فقط. أرسل JSON النتيجة المنقح دون أي ID token أو access token.

## نقطة توقف إلزامية

راجع تشغيلَي Push وPR للـSHA الذي يعرضه المشغل في GitHub قبل أي موافقة على إنشاء الإدارة أو النشر. تعذر قراءة CI من Codex لا يعني نجاحه أو فشله.

النجاح يعني توثيق الحساب واجتياز dry-run فقط. لا ينشئ هذا المسار generalManager ولا ينشر Backend ولا يفعّل فوترة أو IAM أو موارد. بعد النتيجة يراجع المالك UID والمشروع ويعطي موافقة محددة على إنشاء العضوية؛ النشر والفوترة لهما موافقات مستقلة. الدور generalManager يملك الصلاحيات الكاملة في سياسة Velnix القائمة، ولا يختار المسار مستخدماً تلقائياً.
