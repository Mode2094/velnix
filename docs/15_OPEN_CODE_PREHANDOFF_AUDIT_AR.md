# Prompt 0 — تدقيق تشغيل وواجهات Velnix بدون تعديلات على الكود

أنت فريق تدقيق متعدد الاختصاصات: Senior Flutter Engineer + Flutter UX/Accessibility QA + Firebase Security Reviewer. افتح هذا المشروع **Velnix v0.4**. أريد **تقريراً قابلاً للتنفيذ دون أي تعديل للمصادر**. ابدأ بقراءة `README.md` و`docs/14_INDEPENDENT_CODE_REVIEW_AR.md` و`docs/10_VIDEO_SECOND_BY_SECOND_AR.md` وسائر الوثائق، وقراءة `lib/` و`test/` بالكامل. لا تبدأ Firebase أو ميزة جديدة أو إعادة تصميم شامل الآن.

**قاعدة الأمان:** لا تكتب مفاتيح API أو حسابات حقيقية. إن احتجت إلى `flutter create` أو تثبيت اعتمادات تغيّر المشروع، أنشئ نسخة مؤقتة مستقلة للفحص، ولا تعدّل حزمة المصدر الأصلية دون موافقتي. لا تقل إن الاختبار ناجح ما لم تنفذ الأمر وتعرض النتيجة.

1. حدد نسخة Flutter/Dart الفعلية من `flutter doctor -v`، وراجع توافق `pubspec.yaml` مع API المستخدمة مثل `Color.withValues` و`DropdownButtonFormField.initialValue`. نفّذ `flutter pub get` و`flutter analyze` و`flutter test` في بيئة فحص، وسجل أخطاء build/lint/test بالتفصيل.
2. اختبر صفحات تسجيل الدخول والرئيسية والطلبات وإضافة/تعديل/تفاصيل الطلب وشركات التوصيل وبطاقات كل شركة والإشعارات والموظفين والصلاحيات وAPI mapping والمزامنة والتقارير والإعدادات. لكل زر وبطاقة ورابط تنقل، سجّل الفعل المتوقع والفعل الذي حصل. لا تخلط بين عناصر **واجهة تجريبية** وتكامل إنتاجي.
3. صور Screenshots للمقاسات: **320، 360، 390، 430، 768، 1024، 1440، 1920 بكسل**، وعلى text scale 1.0 و1.5 و2.0. اختبر RTL والأجهزة الأفقية وارتفاع لوحة المفاتيح وسلامة Safe Areas، والتباين، ارتفاع صفوف/بطاقات الحالة، عدم قص النص العربي، وضوح الخط، المسافات والتسلسل البصري، وعدم ظهور overflow/RenderFlex أو شريط تنقل مقطوع. أنشئ جدول QA لكل شاشة/قياس مع رابط الصورة أو الوصف إن تعذر الالتقاط.
4. اختبر الأدوار الخمسة فردياً. **الجميع ينشئ طلباً**، لكن مرئيات الطلبات والمبالغ وإجراءات الإدارة تختلف. موظف المبيعات لا يرى مدخل بيانات غير مرتبط به. جرّب منع تعديل شركة أو موظف دون صلاحية، ومنع تصعيد الامتيازات، وتعطيل الحساب، ومنع الحذف النهائي للطلب، وحالات الشحن التي لا يجوز تغييرها يدوياً. تأكد أن بيانات فريق آخر لا تظهر عبر تفاصيل طلب محفوظة أو العودة للخلف.
5. تدقيق البطاقات: في الرئيسية «طلبات شركات التوصيل» **جزء من** «جميع الطلبات»؛ كل بطاقة فيها إجمالي وحالات/أعداد ومبالغ حسب الصلاحية، والضغط يفتح القائمة المفلترة الصحيحة. وفي صفحة شركات التوصيل، كل شركة تعرض بياناتها وحدها، لا بيانات شركات أخرى. طابق الفيديو وفق `docs/10_VIDEO_SECOND_BY_SECOND_AR.md` ولكن لا تطالب بمزايا المتجر والمخزون والمالية الملغاة.
6. دقق حالة إنشاء/تعديل الطلب والهواتف والقيم والأسماء، وسجل الأحداث، وسلوك زر العودة/إلغاء النموذج، والفلاتر المركّبة، والحالات الفارغة والأخطاء. راجع مبدأ الفصل المقبل بين `DemoStore` وFirebase، والمخاطر التي لا يصلحها تعديل UI فقط.
7. سلّمني التقرير **مرتّباً حسب Critical / High / Medium / UX polish**، مع المسار والسطر والتأثير وخطوات إعادة إنتاج المشكلة وصورة الشاشة إن أمكن واقتراح إصلاح محدود. اذكر هل يمكن اعتماد التصميم أم لا، وما العوائق الحالية، وخطة إصلاح أولية من دون تعديل أي ملف.

**حدود المرحلة الأولى ثابتة:** نظام إدارة الطلبات وخمس صلاحيات ومركز شركات التوصيل وربط فعلي **لشركة واحدة فقط في مرحلة البناء** مع مزامنة حالات عكسية. لا متجر إلكتروني، لا كتالوج منتجات، لا جرد مخزون، لا مالية متقدمة، لا نشر Google/Apple، ولا وعود بربط كل شركة من مجرد كتابة API URL.
