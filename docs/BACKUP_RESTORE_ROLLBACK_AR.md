# خطة النسخ والاستعادة والتراجع — مراجعة فقط

لم تنفذ أوامر backup/export/import أو إنشاء bucket أو حساب أو سياسة أو Deploy. التشغيل يحتاج مشروعاً تجريبياً وصلاحيات وميزانية وموافقة المالك. لا تختبر على إنتاج ولا بيانات عملاء حقيقية.

## السياسة التي يعتمدها المالك

حدد RPO وRTO والاحتفاظ وتواتر النسخ والمنطقة والتكلفة ومسؤول الاستعادة والمراجعة. لا توجد أرقام SLA مفترضة. احفظ النسخ مشفرة في مخزن خاص منفصل بصلاحيات وaudit وretention معتمدة، دون روابط عامة أو Git/CI artifacts. اختبر اكتمال snapshot وحدود الكتابة أثناء النسخ؛ سجل الوقت وproject ID ونسخة schema وSHA وhash manifest، لا بيانات السجلات.

## ما يجب نسخه

- Firestore: جميع collections وsubcollections الفعلية، بما فيها الطلبات ومراجعاتها/سجل audit، العضويات والإعدادات والشركات وأسرارها المشفرة، idempotency/inbox والإشعارات وبيانات الأجهزة. راجع جرداً من المشروع وقت التنفيذ؛ تصدير مجموعة الأب وحدها لا يكفي دون التأكد من نطاق export الرسمي.
- Firebase Auth منفصل عن Firestore: UIDs وprovider links والمستخدمون وبيانات استعادة كلمات المرور وفق أداة Firebase المعتمدة. أي hash/password parameters ملفات اعتماد شديدة الحساسية؛ هوية backup منفصلة، لا تمنح صلاحية استخراج hashes لهوية التطبيق.
- قواعد Firestore وفهارسه وAuth/App Check/FCM/domain configuration وIAM/APIs وجدولة Functions ومراجع KMS وإصداراته وملفات تهيئة المنصات. Firebase config وFirestore export لا ينسخان كل هذه الخدمات تلقائياً.
- مصدر Git وlockfiles وtoolchain pins وartifacts الموقعة ومعلومات الإصدار والبيئة. حفظ signing/APNs/vendor credentials حصراً في خزنة المالك المشفرة خارج Git، بمراجعة وصول وتعاف منفصلة.

KMS ciphertext غير قابل للاستعادة دون المفتاح الأصلي وإصداره وصلاحية فكّه. لا يمكن تعويض مفتاح مدمر بنسخ مرجعه أو إنشاء مفتاح جديد بالاسم نفسه. احتفظ بالإصدارات اللازمة وتحقق من سياسة التعطيل/التدمير والاستعادة قبل اعتماد النسخ، دون طباعة الأسرار.

## تجربة استعادة معزولة لاحقاً

1. أنشئ الهدف المنفصل بعد التفويض. اعزل الخروج إلى الشركة والإشعارات؛ لا تعتمد على restore ثم تعطيل الشركة بعد بدء triggers. أوقف الجدولة/التنفيذ الخارجي مسبقاً واستخدم هوية لا تملك إرسال FCM أو استدعاء الشركة أثناء الفحص. لا تستخدم مفاتيح إنتاج في الهدف.
2. تحقق من manifest ووقت النسخ وإصدارات المصدر. استعد Auth وFirestore بتسلسل موثق يمنع المستخدمين من الدخول أثناء عدم تطابق العضويات؛ طابق UIDs وroles/supervisor/authorizationVersion وحالة الحساب، لا تنشئ عضويات تلقائياً لمجرد Auth.
3. استعد القواعد والفهارس وانتظر READY وراجع IAM/KMS. لا تعطي مشروع الاختبار وصولاً إلى مفتاح إنتاج لحل مشكلة الاستعادة؛ استخدم نسخة بيانات اصطناعية مشفرة بمفتاح Staging.
4. افحص counts/revisions/audit/idempotency/inbox والروابط. tokens الأجهزة المستعادة غير موثوقة للتجربة؛ أبق الإشعارات معطلة وأعد التسجيل باختيار مستخدم تجريبي.
5. راجع pending/processing وleases وattempts وacknowledgements، وحالات sending/needs_review للشحن. لا تصفر idempotency أو تعيد إرسال تلقائياً: snapshot قد يكون أقدم من نجاح خارجي، وFirestore لا يتراجع بالشحنة أو الإشعار لدى المزود. التسوية مع سجل sandbox شرط قبل أي استئناف.
6. يبقى Click معطلاً حتى استيفاء بوابته؛ لا تستخدم generic كبديل. اختبر الدخول والصلاحيات والدورة الداخلية بأسماء اصطناعية ثم سجل RPO الفعلي وRTO الفعلي والعيوب مقارنة بالأهداف.
7. لا تستأنف التشغيل قبل مراجعة مالك التجربة. سجل التقرير دون payload أو passwords أو tokens، واحذف نسخ الاختبار حسب retention المعتمد.

## التراجع عن إصدار

ثبّت release manifest: SHA، dependency locks، قواعد وفهارس/schema، إعدادات المشروع العامة، artifact hash وتوقيعه. حدد آخر نسخة متوافقة وآمنة قبل التحديث؛ لا تعتمد أن أي commit قديم صالح للتراجع.

التراجع عن Web/Android/iOS وFunctions لا يرجع تلقائياً Firestore أو Auth أو IAM أو الشحنات أو الإشعارات. راجع توافق old/new schema وcallables والleases قبل تبديل artifact. استبق التحديث بتجربة forward/backward على Staging؛ إذا كان الرجوع يكسر الصلاحيات أو schema فاعتمد إصلاحاً أمامياً بدلاً من نسخة غير آمنة.

لا ترجع إلى نسخة تفقد fencing أو حماية الصلاحيات أو حظر Click الذي أدخل في e005c66. لا تحذف سجلات audit أو طلبات جديدة لإخفاء مشكلة. أوقف الإرسال الخارجي عند الالتباس، واحفظ السجل والمراجع قبل أي إصلاح تشغيلي. قرارات مالية أو إلغاء لدى الشركة لا تُعكس باستعادة قاعدة البيانات.

الإغلاق يتطلب تمريناً فعلياً منفصلاً واسترجاعاً ناجحاً للعضوية والأحداث وKMS مع إثبات عدم إنشاء شحنات/إشعارات أثناء العزل. الوثيقة وحدها ليست backup ولا اختبار استعادة.
