# تقرير مراجعة Velnix v0.3 — قبل تسليم المشروع إلى Open Code

## قرار الجودة

**هذه نسخة Flutter للواجهات والمنطق التجريبي فقط، وليست نسخة إنتاجية مكتملة.** أُجري فحص ملفات شامل، ومقارنة ثانية بثانية بالفيديو (79 لقطة)، ومراجعة منطق تنقل وصلاحيات. **لم يُجرَ تشغيل Flutter أو عرض على محاكي أو متصفح أو تشغيل flutter analyze/test** لأن Flutter SDK غير مثبت ولا تتوفر شبكة تنزيل في بيئة الفحص. لا يجوز وصفها بأنها خالية من أخطاء البناء أو التجاوب المرئي.

## أهم العيوب التي عولجت في النسخة 0.3

1. إسناد شركة توصيل من نموذج الطلب أصبح مشروطاً بصلاحية إرسال الطلب لشركة التوصيل.
2. منع القفز اليدوي إلى حالات تُفترض قادمة من موصل شركة التوصيل (مثل تم التسليم)؛ إجراءات الموظف الداخلية محددة وفق انتقالات مسموحة.
3. إخفاء مجاميع المبالغ وبطاقات الأموال في الشركات عن دور المستودع.
4. فتح شاشة بطاقات شركات التوصيل للعرض التشغيلي لكل الأدوار، وحصر إعدادات الشركة/الـAPI بالمصرّح له.
5. تخصيص الإشعارات حسب المستخدم، مع استقلال تعليم الإشعارات كمقروءة لكل شخص.
6. منع دخول الحسابات الموقوفة، وعدم ظهور طلبات لها بعد التعطيل.
7. تقييد إدارة حساب المدير العام؛ لا يمكن لحساب إداري مفوّض التحكم به.
8. تحسين شريط التطبيق على الشاشات الضيقة، وتنقل جانبي للابتوب وشريط سفلي للهاتف.
9. تخطيط متجاوب لحقول المستلم على هيئة عمود أو عمودين حسب المساحة؛ قيد مناسب لعرض نماذج سطح المكتب.
10. إضافة فلتر شركات التوصيل داخل قائمة الطلبات، وتحسين الوضوح النصي والتباين.

## فحوص غير منفذة ويجب إجراؤها قبل اعتبار التصميم معتمداً

- `flutter pub get && flutter analyze && flutter test`.
- محاكاة Pixel widths: 320، 390، 768، 1024، 1440، و1920 مع ارتفاعات متعددة وتكبير نص 200%.
- اختبارات هواتف Android فعلية، Safari/iOS على جهاز Mac، ومتصـفح سطح مكتب Chrome/Edge.
- اختبار أزرار التنقل والإجراءات عبر الأدوار الخمسة؛ إيقاف حساب/صلاحيات/أخطاء الشبكة/استرداد البيانات.
- اختبار أمان Firestore Rules بإجراءات غير مخوّلة خارج Flutter، وتحقق Cloud Functions من صلاحيات API.
- تحميل كبير من الطلبات وpagination وتقارير مؤشرات واقعية.

## حدود المرحلة الأولى الثابتة

يدخل ضمن المنتج النهائي المُخطَّط: إدخال ومتابعة وإدارة الطلبات، المدير العام والمدير والمستودع التشغيلي والمبيعات ومدخل البيانات، الصلاحيات، شركة توصيل **واحدة** بتكامل حقيقي إذا قُدّمت API صالحة، استقبال حالات التوصيل ومطابقتها، عدم الحذف النهائي، بطاقات لوحة التحكم. لا يدخل المتجر أو إدارة المخزون أو النشر على Google Play أو App Store. ملفات Flutter الأولية ليست دليلاً على اكتمال المرحلة أو تحقق العقد.

## ملاحظة تقنية حاسمة

شركة التوصيل الخارجية قد تدعم Push عبر webhook أو polling فقط، وقد تفرض متطلبات أو رسوماً وتمنع بعض الحالات. لا يمكن ضمان التحديث العكسي لكل شركة من دون فحص وثائقها. مفاتيح API يجب أن تبقى في الخادم/Secret Manager ولا تدخل في التطبيق المنشور. بيانات Firebase يجب أن تُعزل على مستوى الجهة/المشروع، والقواعد هي مرجع صلاحيات القراءة والكتابة.
