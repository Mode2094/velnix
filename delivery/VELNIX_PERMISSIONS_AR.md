# VELNIX — الأدوار والصلاحيات

## 1. الأدوار

| الدور | الوصف |
|---|---|
| مدير عام (generalManager) | كامل الصلاحيات؛ إدارة الشركات والفريق والإعدادات والمراجعات الاستثنائية |
| مدير (manager) | متابعة الطلبات والتقارير حسب الصلاحيات الممنوحة |
| موظف مستودع (warehouse) | تجهيز الطلبات وتحديث حالتها |
| مبيعات (sales) | متابعة طلباته/فريقه وإدخال الطلبات |
| مدخل بيانات (dataEntry) | إدخال الطلبات ومتابعة طلباته فقط |

## 2. الصلاحيات (تُمنح صراحةً)

`viewAllOrders`، `editAllOrders`، `updateOrderStatus`، `sendToDelivery`، `viewReports`، `viewAmounts`، `manageEmployees`، `manageCompanies`، `viewSync`، `viewAudit`، `manageSettings`.

- **المدير العام** يملك كل شيء ضمنيًا.
- **المدير** يحتاج منحًا صريحًا للصلاحيات.
- لا يمكن منح صلاحية أعلى من صلاحية المانح.
- لا يمكن للموظف رفع صلاحياته.

## 3. عزل البيانات (Tenant Isolation)

- **مبيعات/مدخل بيانات:** يرون فقط طلباتهم/طلبات فريقهم المرتبط.
- **المبالغ:** تُخفى (`amount`) عمّن لا يملك `viewAmounts` أو ليس منشئ الطلب.
- **الشركات:** فقط الشركات ضمن نطاق المستخدم؛ لا تعديل شركة خارج النطاق.
- **الإدارة:** قوائم الفريق/التدقيق/المزامنة محصورة بالصلاحيات المناسبة.
- يتم فرض كل ذلك **خادميًا** في Cloud Functions وليس بإخفاء أزرار الواجهة فقط.

## 4. قواعد الحماية الأساسية

- لا يُعطَّل **آخر مدير عام فعّال**.
- لا يعتمد المستخدم طلب انضمامه بنفسه.
- لا تُعدَّل شحنة بعد الإرسال أو أثناء الإرسال (`sending`/`sent`/`needs_review`).
- لا يُغيَّر ربط مدخل البيانات بمسؤول المبيعات إلا من مخوّل وبقواعد الخادم.
- `manageEmployees` مطلوب لكل عمليات الفريق (إضافة/تعديل/حذف/إعادة كلمة مرور).

## 5. الحسابات المحمية

- الحسابات الإدارية محمية؛ لا يمكن لغير المدير العام تعديل حسابات الإدارة.
- `authorizationVersion` تُبطِل الصلاحيات القديمة فورًا عند أي تغيير دور/إشراف.
